How to Think Like a Network Analyst

These steps describe how a SOC analyst approaches unusual network traffic. Use them as a guide when reviewing the findings above.

  1. Observe the unusual behaviour. What pattern caught your attention? High packet count? An unfamiliar destination? Unusual protocol activity?
  2. Identify the source and destination. Which host generated the traffic? Where was it going? Is the destination internal or external?
  3. Determine which protocol is involved. TCP, UDP, ICMP, DNS, and ARP all behave differently. Understanding the protocol helps you assess whether the traffic is expected.
  4. Establish whether the activity is expected. Is this the kind of traffic you would normally see from this host? Does the volume make sense? Is the timing unusual?
  5. Look for supporting indicators. Does the same host appear in multiple findings? Are there other hosts showing similar patterns?
  6. Correlate with other security telemetry. Network traffic alone rarely tells the whole story. Check endpoint logs, authentication events, and any available alerts from other systems.
  7. Decide whether further investigation is required. Not every anomaly is an incident. Make a reasoned judgement based on the available evidence, context, and possible benign explanations.
“An anomaly is a starting point for investigation, not proof of compromise. Always consider the most likely explanation first.”

How to Export a Wireshark CSV

  1. Open Wireshark and capture traffic on an authorised network interface.
  2. Stop the capture when you have enough data.
  3. Go to File → Export Packet Dissections → As CSV…
  4. In the export dialog, choose All packets and select the columns you want (No., Time, Source, Destination, Protocol, Length, Info).
  5. Save the file with a .csv extension.
  6. Upload the file into this tool using the upload area above.

Important: Only capture traffic on networks and systems you own or have explicit written authorisation to monitor. Capturing network traffic without authorisation may be illegal.

Detection Rules Used in This Tool

Rule 1 — High Packet Volume
One source generates more packets than the configured threshold
May indicate legitimate high-volume activity, file transfers, scans, or automated tools.
Rule 2 — Possible Host Scanning
One source contacts an unusually large number of unique destinations
May indicate host discovery, network scanning, or distributed application behaviour.
Rule 3 — Possible Port Scanning
One source contacts many different ports on the same destination
Detects where the Info field reliably exposes port numbers. May indicate port scanning or service discovery.
Rule 4 — High ICMP Activity
One source generates an elevated number of ICMP packets
May indicate ping sweeps, network troubleshooting, monitoring tools, or denial-of-service activity.
Rule 5 — High DNS Query Activity
One source generates an elevated number of DNS queries
May indicate normal browsing, automated tools, misconfiguration, or beaconing behaviour.
Rule 6 — Repeated Source-to-Destination Communication
One source sends a high number of packets to the same destination
May indicate normal application traffic, persistent connections, or unusual automated activity.

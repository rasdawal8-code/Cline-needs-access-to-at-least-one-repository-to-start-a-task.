    Windows Security Event ID Reference

    These are the Event IDs this tool recognises. Understanding what each one means is the foundation of Windows security event analysis.

    4624
    Successful Logon
    A user successfully authenticated to the system. This is normal activity but important context when correlated with failed logons or unusual hours.
    4625
    Failed Logon
    An authentication attempt failed. A single failure is usually benign. Multiple failures for the same account may indicate a wrong password, a stale service credential, or a brute-force attempt.
    4720
    User Account Created
    A new Windows user account was created. May be legitimate administration or an attacker establishing persistence.
    4726
    User Account Deleted
    A user account was deleted. Could be routine offboarding or suspicious account manipulation.
    4728
    Member Added to Global Security Group
    A user was added to a global security group. If the group is privileged (e.g. Domain Admins), this warrants careful review.
    4732
    Member Added to Local Security Group
    A user was added to a local security group. If the group is Administrators or similar, this deserves investigation.
    4688
    Process Created
    A new process was started. With process creation auditing enabled, this can reveal commands executed on the system.
    4104
    PowerShell Script Block Logged
    A PowerShell script or command was executed. Provides valuable visibility into scripts run on the endpoint. Obfuscated commands deserve additional scrutiny.
    7045
    Service Installed
    A new Windows service was installed. May be legitimate software installation or potentially attacker-established persistence.
    1102
    Security Audit Log Cleared
    The Windows Security event log was cleared. Can be legitimate maintenance but is also associated with attackers removing evidence. Should normally be investigated.

    How to Think Like a SOC Analyst

    These steps describe how a SOC analyst approaches Windows security events. One event rarely tells the complete story — context and correlation are everything.

    1. Identify the event. Which Event ID triggered? What does it mean? Use the Event ID Reference tab as a guide.
    2. Understand what happened. A logon attempt? An account change? A privilege grant? Be precise about what the event actually records.
    3. Identify the affected user or system. Which account is involved? Which computer generated the event? Is this a user account, a service account, or a machine account?
    4. Determine whether the activity is expected. Is this user normally active at this time? Is this the computer they usually log into? Is this a known administrative action?
    5. Look for related events. Did failed logons precede a successful one? Was an account created and then immediately granted privileges? Were logs cleared after suspicious activity?
    6. Correlate authentication and privilege activity. Authentication events, privilege changes, and process creation events together tell a richer story than any single event alone.
    7. Gather additional evidence. Check endpoint telemetry, network logs, and any available MFA or VPN records to build context.
    8. Decide whether escalation is required. Make a reasoned judgement. Consider benign explanations. Document your reasoning.
    “One security event rarely tells the entire story. Analysts build context by correlating multiple events across time.”
    “A detection is a reason to investigate, not proof that an attacker is present.”

    How to Export Windows Security Events as CSV

    1. Open Windows Event Viewer (search for it in the Start menu).
    2. In the left panel, navigate to Windows Logs → Security.
    3. Optionally, click Filter Current Log in the right panel to filter by specific Event IDs or time range.
    4. To export, go to Action → Save All Events As… and choose CSV (Comma Separated) as the file type.
    5. Alternatively, use PowerShell: Get-WinEvent -LogName Security | Export-Csv -Path security-events.csv -NoTypeInformation
    6. Upload the resulting CSV file into this tool.

    Note: Windows Event Viewer CSV exports may not include all fields depending on how they are exported. PowerShell exports tend to be more complete. If certain columns are missing, the tool will notify you and work with whatever data is available.
